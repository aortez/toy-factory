# Mixed-condition persistence pilot: frozen protocol

Test whether a small search can improve across world seeds and both existing
disturbance schedules. Keep persistence-v2 fitness, all ecology, controller
interfaces and firmware unchanged. Species/founder-family diversity is diagnostic,
not a reward, constraint or tie-breaker. This is one exploratory search, not
model promotion, environment qualification or a final generalization test.

## Frozen environment and split

Copy the exact native mutation/evaluation/replay executables and original model
`dc5e849d` from `garden-training-pilot-v1`, manifest SHA-256
`9c9dc94e44cee155b4d8a83276339936d17e97cce4b995259faed4cd31059950`.
Do not start from the previous pilot winner or rebuild native code. Preserve
the original bundle, binary/model hashes and this protocol in the new bundle.

Environment: 512 nodes, eight seed slots, wide-v1 dispersal, headroom-v1 uptake,
leaf-maintenance-v1, rainfed-crowded, selective leaf policy, neural-no-night-growth.
No gardener/irrigation, bottom drainage, seed reserve or reserve-growth adapter.
Each trial runs from reset to day 192 (737280 ticks), scores (158,190]
(`606720 < tick <= 729600`) with fixed terminal follow-up to 737280. Never run
through the known 256-day plant-age boundary.

Use both existing patch-death-v1 schedules: fresh-1 `e4d65e6f`, fresh-2 `17c29444`.
Their explicit order is fresh-1 then fresh-2, followed by seed order below.

- Development seeds, generated by `trial_seeds(0x6d697864, 4)`:
  `5fd2b58f`, `acc67fa4`, `f9bd207c`, `4aff6bf2`.
- Review seeds, generated by `trial_seeds(0x726d7833, 4)`:
  `2109e05f`, `d21d2a74`, `876675ac`, `34243e22`.

These literals had no matches in local source/docs/reports before this protocol;
this is not a claim about all possible private history. Both panels contain eight
conditions. Review world seeds never enter automated selection. The schedules
are familiar, not held-out schedules. There is no final test set in this pilot.
Do not replace poor/empty worlds or extend the budget after viewing results.

## Search and evidence budget

Serial deterministic (1+lambda): original incumbent plus three generations of
three offspring each, ten candidate models / 80 development trials total. Each
generation's three offspring come from its unchanged generation-start parent.
Use the existing native mutation algorithm, 32 parameter mutations per offspring,
search RNG `0x6d697833`, and unchanged lexicographic six-component aggregate
fitness. Strictly better replaces the incumbent; exact ties retain it (then the
first strictly better offspring in canonical order). No diversity tie-breaking.

After generation zero and each completed generation, preserve its model bytes
and evaluate all eight review conditions. Capture every review condition at
day 192 using the shared production renderer: 32 scored review trials and 32
native 240x240 PNG/RGB565 frames, including unchanged champions and failed
worlds. This pilot deliberately uses only the late snapshot, unlike the previous
three-timepoint pilot; no early-lifecycle visual claim is made. Gallery rows are
fixed schedule/seed conditions, columns are generations 0/1/2/3, not selected wins.
Rendering/review use separate reset processes and cannot affect selection or RNG.

Repeat the entire 80-trial search without review/capture and require identical
candidate model bytes, RNG records, scores, final hashes and champion history.
Thus 192 scored trials total (80 development + 80 repeat + 32 review), not 192
independent search observations. Independently double-render every review frame,
checking state/checkpoint identity, raw length/CRC and exact repeated pixels.
Every scored trial exports full bounded lineages/seeds and must match the unchanged
Python fitness evaluator. Archive source/input/executable hashes, exact settings,
all candidates, review generations, ledgers and timings. Reject incomplete panels,
changed inputs, ledger overflow, score/replay mismatches and missing images.
Publish a complete manifest only after full artifact/selection reanalysis passes.

## Report and stop

For each generation, report development and review aggregates relative to the
unchanged original model; include per-condition win/tie/loss, both schedule
aggregates and leave-one-world-seed-out sensitivity (remove both schedules
together). Report terminal tiers, species/founder-family histograms, successful
recruitment and exact renewal/live-time attribution separately from fitness.
Do not equate one-species living endpoints with seed-bank extinction, or one
shared controller with independent neural lineages. No causal resource claims
from compact lifetime records.

Stop after three generations regardless of result. No new sweep, objective or
ecology change, commit, push, or device deployment is included. Discuss the
numeric/visual evidence and its finite-window/population-time/selection limits
before deciding the next experiment.
